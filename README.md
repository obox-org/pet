# 宠物（obox 扩展）

桌面宠物：在屏幕右下角养一只鲸鱼娘——无边框透明置顶窗体里的精灵帧动画，喂食 / 洗澡 / 玩耍影响饥饿度、清洁度与心情，挂机攒成长值升级。

这是一个**后台扩展**：不在启动器 / 导航区出现，也没有 App 卡片（design D-12）。对外可见面只有三处：

| 可见面 | 位置 | 说明 |
| --- | --- | --- |
| 设置页「扩展 → 宠物」 | 宿主设置页（宿主渲染） | 1 个 toggle + 3 行进度条 + 1 个只读诊断位 |
| 宠物 overlay 窗体 | 屏幕右下角 | 220×460 透明、无边框、置顶、不占任务栏 |
| 状态栏诊断位 | 宿主状态栏右侧（`pet.status`） | 常态显示「宠物」；出错时显示可执行的中文文案 |

## 玩法与数值

### 三属性与衰减

| 属性 | 衰减速率 | 过低阈值（< 30） | 恢复途径 |
| --- | --- | --- | --- |
| 饥饿度 | **-1 / 分钟** | `hungry`（等待投喂动画） | 喂食 +5 |
| 清洁度 | **-10 / 小时** | `dirty` | 洗澡 +15 |
| 心情 | **-5 / 小时** | `sad` | 玩耍 +5、摸头 +1 |

- 结算时钟每 **15 秒**一 tick，采用**惰性结算**：只在运行期间计时，obox 重启 / 窗体重建后按时间差一次补齐（时间回拨时 dt 钳 0）。
- **联动记账**：饥饿 / 清洁每累计**下降** 10 点 ⇒ 心情 -1；每累计**恢复** 10 点 ⇒ 心情 +1（零头跨结算周期保留）。经恢复联动上涨的心情**上限 95**——满心情要靠玩耍 / 摸头（互动途径可到 100）。
- 内部保留浮点、显示向下取整；三属性钳 [0, 100]。

### 互动与道具

| 互动 | 效果 | 消耗 | 动画轨 |
| --- | --- | --- | --- |
| 喂食 | 饥饿度 +5 | 小鱼干 ×1 | `jumping`（开心地吃） |
| 洗澡 | 清洁度 +15 | 沐浴泡泡 ×1 | `waving`（摆臂 ≈ 擦洗） |
| 玩耍 | 心情 +5 | 无 | `running`（原地跑动） |
| 摸头（点击宠物本体） | 心情 +1 | 无 | `waving` |
| **拖动**（按住精灵左键移动） | 窗体跟随换位，松手把坐标写进 `state.json`（重启回到该位置） | 无 | 无（移动的是窗体，不切轨） |
| **随机表演**（自发，非用户触发） | **非打盹时每 10 秒**从 7 项"表演型"动作里随机抽一条**原地**播一轮（约 1.4–1.8s，含 `run-left`/`run-right` 两条侧向原地跑），无气泡；**播完立即回到呼吸待机**（页面侧锁存 + 看门狗，"一轮 + 500ms"内回落，不等入口下一次推送）；不耗道具、不改任何数值、不推进"入睡"计时 | 无 | `jumping` / `waving` / `running` / `running-left` / `running-right`（各一轮） |

- 摸头有 **5 分钟冷却**（300s）：冷却内点击仍播反馈动画但不加分，气泡为 `摸过头啦，让鲸鱼娘歇口气～`（**不含剩余分钟数**——见下方文案口径）。
- **互动动画的回落（卡 19 · R54）**：入口在 transient 到期时**主动推送一次**（`pet-transient` 一次性定时器；`api.timer` 只收 1–86400 的整数秒 ⇒ 按 `ceil(该轮时长/1000)` 秒排，并在触发时校验真的到期）。所以点喂食/洗澡/玩耍/摸头后，精灵最迟在**该轮时长 + 1 秒**内回落呼吸/当前基础态（属性过低时回 `hungry`/`dirty`/`sad`），不再等下一次 15 秒结算 tick。自发表演的"播完即回呼吸"另由页面侧锁存（`anim.self` + 看门狗）负责。
- 道具不足时不扣不改，气泡提示：`没有小鱼干了，多陪我工作一会儿吧～` / `没有沐浴泡泡了，多陪我工作一会儿吧～`。
- 拖动只响应**鼠标左键**，页面按帧（rAF）合并增量发 `pet.drag{phase,dx,dy}`，入口累加自记坐标后调 `api.overlay.setPosition`；**几何钳位（工作区/任务栏）由宿主兜底并回传钳后坐标**，入口只拒绝 `NaN`/`Infinity`（入口拿不到显示器工作区，自己算不出边界）。拖动期间抑制随机表演与入睡判定、不弹气泡。
- **随机表演**（增补轮 Q16，取代原"2–5 分钟原地小跑"）：入口用**宿主级** `api.timer.setInterval('pet-perf', 10, …)` 每 **10 秒**从随机集（`eating` / `bathing` / `petted` / `playing` / `trot` / `run-left` / `run-right`，单一来源 `lib/constants.js`）抽一条播**一轮**（时长 = 该轨真实帧时长之和，1.4–1.8s），播完回落判定。**状态指示轨（`hungry`/`dirty`/`sad`）与 `sleep` MUST NOT 参与随机**——随机摆出"饿了/脏了/难过"会与真实数值脱节；**打盹期间不触发**；优先级**低于真实互动**（用户随时可抢占它）、**高于状态指示轨**（只暂时改姿态，不改数值）。副作用为零：不消耗道具、不改任何属性/库存/成长值、不弹气泡、不推进也不重置 `lastInteractAt`。`run-left`(row2)/`run-right`(row1) 只**原地**播帧，**绝不**调 `setPosition`（宠物不位移）。

### 文案口径（design D-16）

- **反馈文案与上游 dsh-pet 逐字一致（摸头 / 喂食五句）**：`咕噜咕噜～被摸摸好舒服！`、`摸过头啦，让鲸鱼娘歇口气～`、`呜哇！小鱼干好好吃！`、`吃饱啦，晚点再喂～`（以上出自上游 `affinity.ts`）、`没有小鱼干了，多陪我工作一会儿吧～`（出自上游 `ledger.ts`）。
- **全部用户可见文案不含数字时间与属性增量数字**：气泡 / 面板 / 三枚图标按钮的可访问名 / 状态栏 / 设置页诊断一律不出现「数字 + 分钟/秒/小时」，也不出现 `+5`/`+15`/`-1` 一类增量数字（增补轮 Q12/Q13 的用户硬约束）。两条正则对文案表全量扫描 0 命中由 `test/actions-text.test.js` 钉住。
- 上游改了这些文案**不会自动跟随**（design R12）：文案表在 `lib/constants.js` 单点维护，跟随上游属新的一次 change。
- 属性数值只在**设置页**以进度条 `{cur}/100` 呈现（宿主渲染）；悬停面板**不显示三属性**（Q13）。

### 挂机与成长

- **挂机经济**：每满 **20 分钟** +1 小鱼干 +1 沐浴泡泡（库存上限各 **20**；首次安装初始 3/3）。窗体销毁期间挂机计时**暂停**，属性衰减继续（关窗期间宠物仍会饿，重新开窗按时间差补齐）。
- **成长值**：基础 **+2 / 小时**，带心情惩罚——心情每缺 5 点再扣 0.1/小时：`rate = max(0, 2 − 0.1 × floor((100 − 心情) / 5))`。
- **等级四档**（按成长值）：

| 成长值 | 等级名 |
| --- | --- |
| 0–49 | 幼鲸 |
| 50–199 | 伙伴 |
| 200–499 | 挚友 |
| ≥500 | 深海羁绊 |

- 其它节奏：连续 **10 分钟**无任何交互 ⇒ 打盹（`sleep`，idle 轨 1.5 倍慢放）；非打盹时**每 10 秒随机表演一轮**（约 1.4–1.8s，无气泡、不耗道具、不改数值，且不推进入睡计时；打盹期间暂停，任一交互唤醒后照常）；气泡 2600ms 自动消失。随机周期（10 秒）远小于入睡阈值（10 分钟），所以"入睡前的可见窗口里几乎必然演过很多轮"这条关系天然成立（`test/actions-trot.test.js` 有断言钉住）。

### 悬停面板

- **悬停面板**（指针命中精灵时淡入，宽 200px，深色玻璃）：等级行（`深海羁绊 · 成长 128`）→ 库存行（`🐟 3 ｜ 🫧 3`）→ **三枚等宽图标按钮、横向一行**（喂食 = 一条小鱼、洗澡 = 泡泡、玩耍 = 球）。**面板不显示三属性**（增补轮 Q13：属性数值只在设置页以进度条呈现），也**不提供关闭/收起宠物的入口**（增补轮 Q15=B：那个语义只由设置页 toggle 承担 = 销毁窗体，见下）。
- 图标是**内联 SVG**（22px、`fill: none` + `stroke: #ffffff`【白色线条】、线宽 1.6、圆头圆角连接），按钮**底色透明**（无渐变）、悬浮时一层极淡白叠加（`rgba(255,255,255,.08)`）+ 描边高亮、键盘焦点环为**白色 2px**；**不用文字标签、不用 emoji、不用图标字体**（运行时零依赖）。中文动作名：**悬浮（或键盘聚焦）即时显示**在图标上方的自绘浮层 `.tip`（玻璃底 + 白字 + 6px 圆角，无延迟），同时保留 `aria-label` 供读屏（不再用原生 `title`——它要等约 1 秒，且会与浮层形成双提示）。道具不足的那一枚显示为禁用态（`opacity .45` + `cursor: not-allowed` + `aria-disabled="true"`，图标形状不变），**但仍可聚焦、浮层照常显示动作名**——键盘用户 Tab 得到它、读屏也会念出这个动作当前不可用，只是点击不会真的发出去。
- **面板开合**：指针在宠物命中区**或落在面板上** ⇒ 显示（面板矩形在面板开启时**必定**参与命中测试，所以指针移到面板上不会把它关掉）；离开 ⇒ **立刻**关闭——`closePanel()` 同步翻转状态位与命中矩形缓存，开合判定（`panelOpen` computed ← 纯函数 `panelShouldOpen`）**不依赖任何过渡动画或延时定时器**，`.panel` 的 120ms 过渡只作用在 `opacity` 上。
- **Tab 顺序**：精灵 → 喂食 → 洗澡 → 玩耍 → 关闭面板；面板展开时焦点落"喂食"，关闭时焦点归还精灵；精灵上 空格/回车 = 摸头，面板打开时 Esc = 关面板（**不关窗体**，关窗体只有设置页 toggle 一条路）。拖动中被拎起来的宠物**不会**弹面板（先把动作做完），松手时指针若仍停在精灵上，面板照常出现。

## 设置页（设置 → 扩展 → 宠物）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 显示宠物（`pet.visible`） | toggle | **关 = 销毁窗体**（真正释放渲染进程与 rAF 帧循环，省 CPU），**不是隐藏**；实测 rAF 窗体单核当量 ≈2.18%，销毁后 0.0ms/10s。再开 ⇒ 重建窗体、按时间差补算属性，状态连续。**隐藏（把宠物收起来）只由本 toggle 承担**——它等于销毁窗体、真省 CPU；面板里没有、也不再有那个入口（面板三枚图标只做喂食 / 洗澡 / 玩耍） |
| 饥饿度 / 清洁度 / 心情（`pet.hunger` / `pet.clean` / `pet.mood`） | progress | 三行进度条，显示 `{cur}/100`：**数值向下取整、条宽不取整**（宿主 progress 渲染口径）；互动后当帧刷新 |
| 诊断（`pet.diagnostic`） | status（只读） | 正常为空；窗体创建失败 / 状态保存失败时显示与状态栏相同的可执行文案（如 `宠物窗体创建失败：<原因>`）。它是**落盘**的设置键：启动成功（窗体建好且状态就绪）后扩展会**无条件**把它写回空、状态栏写回「宠物」，因此上一会话残留的失败文案不会跟到新会话 |

## 最低宿主版本

需要 **`apiVersion ≥ 2` 的 obox**（宿主仓库 `package.json` 当前 `apiVersion: 2`）。本扩展依赖 v2 才有的能力：

- `api.overlay.create / destroy / setMouseThrough / setPosition`：透明 overlay 窗体——不注册卡片、不进启动器 / 导航区，作用域限定只能操作本扩展自己创建的窗体，宿主停用 / 卸载扩展时自动回收；`setPosition`（拖动换位用）按主显示器工作区**兜底钳位**并在成功回包里带上**钳制后的实际坐标** `position`，入口用它校正自记位置；
- 设置页 `progress` 字段类型（三行属性进度条）。

扩展清单已声明 `apiVersion: 2`；老宿主会按门槛**拒绝加载**，扩展在管理器里标红并提示：`需要 obox API v2 或更高（当前 obox 为 vN）`（`src/renderer/src/core/manifest.ts:35`）。

## 安装与调试

- **安装**：扩展管理器工具栏「安装扩展」选 `out/pet-1.0.1.oix`，或把 `.oix` **拖进**扩展管理器视图；安装（含同名覆盖升级）成功后**立即热生效**，无需重启。安装位置 `<userData>/extensions/pet_chenzhi/`（目录名 = `<name>_<author>`）。
- **调试（不安装直接加载）**：

  ```bash
  # 打包版（已安装 obox）
  obox.exe --remote-debugging-port=9333 --debug-extension pet@C:\绝对\路径\extensions\pet

  # 开发版（在 obox 仓库执行；参数要经两个 -- 才能传到 electron）
  npm run dev -- -- --remote-debugging-port=9333 --debug-extension pet@<路径>
  ```

  调试扩展经 `app://debug/pet/` 加载：不写 userData、管理器显示「调试中」、不可卸载、重启消失；改代码后**重载窗口**生效（入口是动态 import，模块缓存不自动失效）。

## 开发

```bash
npm install        # 构建期依赖（vite + vue + @vitejs/plugin-vue）；运行时零依赖
npm test           # node --test：196 条测试覆盖 lib/** 纯函数、入口接线与 app/** 的源码/纯函数断言（零依赖，不装 node_modules 也能跑）
npm run build      # 构建 Vue 子应用（app/ → dist/：index.html + assets/*.css + assets/*.js，共约 95 KB = JS 90 KB + CSS 4 KB）
npm run pack       # 先 build 再打包 → out/pet-1.0.1.oix（带打包清单回读自检，失败即删产物退出非 0）
```

- 校验清单（在 obox 仓库根执行）：`node scripts/validate-manifest.mjs extensions/pet/manifest.json`。
- 入口 `index.js` 是**纯 ESM JavaScript**：不能 `import` npm 包、不能 `import` 宿主源码，只能用注入的 `api`；顶层零副作用，全部业务数值在 `lib/*.js` 纯函数里（不碰 api / DOM / 定时器），阈值与文案的单一来源是 `lib/constants.js`。

### 打包清单（`scripts/pack.mjs`）

`.oix` 就是 zip，按**白名单**收集（guides-user.md 第 6 节的四条硬性要求全部满足）：

- **根文件**：`manifest.json`（必须是 zip **根条目**，无目录前缀、无 `./`）、`index.js`（`manifest.main` 指向的入口）；
- **目录（递归）**：`dist/`（Vue 子应用构建产物）、`assets/`（精灵图集 + 上游 LICENSE + PROVENANCE）、`lib/`（9 个纯函数模块——入口 `import './lib/…'`，**缺一个都会加载失败**）；
- **永不进包**：`data/`（扩展运行时数据目录，含 `data/` 的包被安装器以 `forbidden-entry` 直接拒收）、`node_modules/`、`out/`、`.git/`，以及源码 / 规格目录 `openspec/`、`docs/`、`test/`、`app/`；
- **回读自检**：打包后重新解析产物的 zip 中央目录，断言必需条目齐全（含全部 9 个 `lib/*.js`）、无禁止前缀、`manifest.json` 为根条目、路径全为正斜杠（无反斜杠 / `..` / 空段 / `./`）、条目 ≤10000、解压总量 ≤512MB；任何一条不过 ⇒ 删除产物并退出非 0。
- 手工复核：`tar -tf out/pet-1.0.1.oix`（`.oix` 就是 zip）。

## 已知平台限制（透明窗体）

以下五条来自 design D-11（Electron 官方局限性逐条对齐），均为**预期行为**而非缺陷。实机验证情况见证据文件 `openspec/changes/pet-desktop-companion/notes/evidence/overlay-feasibility.md`（Windows 11 25H2 + Electron 44.6.0，下称「证据」）：

| # | 限制 | 实机验证 | 说明 |
| --- | --- | --- | --- |
| 1 | `transparent` 依赖 DWM 合成：被组策略关闭时透明失效，退化为不透明 | ✗ 未测（证据 §6-5） | Win8+ 默认开启；窗体不透明时先排查 DWM |
| 2 | `transparent` **创建后不可运行时切换** | ✗ 官方限制，未实机复现（证据 §6-5） | 因此只在 overlay `create` 时决定透明；toggle 只做销毁 / 重建，不改透明属性 |
| 3 | 全屏独占应用下 `alwaysOnTop` 窗体可能被遮挡 | ✗ 未测（证据 §6-5） | 全屏游戏 / 放映时宠物可能看不见 |
| 4 | 打开 DevTools 时窗口变**不透明** | ✗ 仅防御性守卫，未主动复现（证据 §6-6） | 透明验收 / 排障**不得开 DevTools**，改用截图取色 |
| 5 | 无逐像素穿透，只能 `setIgnoreMouseEvents` 做**整窗**切换 | ✓ 已实机验证（证据 §2/§5/§7） | 穿透态点击落桌面（右键菜单截图 + `WindowFromPoint` 双证据）；非穿透态**整窗**捕获点击——指针命中精灵 / 面板期间，220×460 内的空白区也会一并捕获，移出后恢复穿透（已知取舍） |

已实机验证通过的相关判据：透明像素（精灵 / 面板之外的点完全透出壁纸色，证据 §1）、销毁窗体省 CPU（证据 §4）、alwaysOnTop / skipTaskbar（证据 §3）。另注：`forward:true` 的命中转发对**注入式**光标移动在本机间歇性失灵，真实鼠标正常（证据 §6-2）——自动化环境排查 hover 问题时先用真实鼠标复核。

## 主题：窗体有意不接主题桥（design D-6）

宠物窗体是桌面上的 **artwork 覆盖层**：精灵用图集原色，悬停面板为**固定深色玻璃**（底 `rgba(15,23,42,0.92)`、描边 `rgba(148,163,184,0.35)`、三枚互动图标用**白色线条** `#ffffff`），**不接主题桥**、不引用宿主 25 个主题 token 中的任何一个。理由：深色玻璃在任何桌面壁纸上都可读，与「宠物是 artwork」的定位一致；这是经用户裁定、已在 design `## UI 视觉规范` 硬约束 1/2 条登记的豁免（退场条件：将来要求跟随主题时回 proposal/design 重定 D-6）。

面板**不使用** `backdrop-filter: blur()`：官方文档明确 CSS blur 无法模糊透明窗口下方的桌面内容，加了只白耗 GPU——玻璃感由半透明底 + 描边实现。

设置页三行进度条、toggle 与状态栏文本由**宿主渲染**，天然跟随宿主主题，扩展无需也未做 token 桥接。
