# design — pet-v2-growth-favor（业务模型重做）

> 输入：`proposal.md` 与 `specs/*/spec.md`（22 条新增 requirement + 4 条删除 + 53 个 scenario）；UI 风格已由用户在固定菜单中选定为**「沿用现有扩展风格」**。

## Context

**现状（v1.0.2，已发版）**：三属性（饥饿/清洁/心情，0–100，按分钟/小时衰减 + 联动）、4 种互动（喂食/洗澡/玩耍/点击）、道具与挂机奖励、随机表演每 60 秒一轮（7 项）、连续 10 分钟无交互打盹（idle 1.5× 慢放 + `打盹中（Zzz）`）、气泡 2600ms、面板为三枚图标（透明底 + 白色线条 + 悬停显名 + 白色焦点环）、设置页 3 行属性进度条 + 开关 + 诊断。

**约束**：

- 宿主能力边界：`api.overlay`（create/destroy/setMouseThrough/setPosition）、`api.settings`（`set`/`get`，字段类型 `boolean/number/text/select/directory/status/progress`）、`api.timer`（整数秒 `setTimeout`/`setInterval`/`clearTimeout`/`clearInterval`）。见 `docs/extension-api/api-reference.md` 的 `api.overlay` / `api.settings` / `api.timer` 小节。
- 浮层窗体（`?obox-window=overlay`）**不注入** `api`：页面通过 `postMessage` 与入口通信（`docs/extension-api/api-reference.md` 的 `api.app.registerWindow`/子窗口消息协议小节）。页面侧**没有**定时器与文件能力，所有状态推进都在入口。
- `progress` 字段：宿主把 `cur` 钳到 `[0,max]` 再向下取整，且**不渲染 description**（`docs/extension-api/manifest-reference.md` 的 `contributes.settings` 小节、`docs/extension-api/themes-settings.md` 的字段类型说明）⇒ 好感超过 650 后进度条会饱和，精确数字必须另用 `status` 行展示。
- 扩展是**受信代码**，可直接调 `window.api`（ADR-0015），本设计不引入新的安全边界。
- 参考实现：`extensions/rdp/src/styles.css`（`--radius: 8px`、`--radius-lg: 10px`、`--label-w: 144px` 等**扩展自有布局变量**）、`extensions/webapp/src/styles.css`、以及本扩展 v1 的 `app/components/PetPanel.vue`（已通过 R53 的白色焦点环基线）。

## Goals / Non-Goals

**Goals（本轮）**

1. 用「成长值 + 好感值」替换三属性体系（只涨不跌、无衰减、无联动、无负面表情）。
2. 好感 10 级 + 10×10 文本池（等级揭示规则）+ 每 5 分钟一条 + 点击冷却文本。
3. 互动收敛为喂食 + 洗澡（各 +1/+1、共享 10 分钟冷却、耗对应道具）；点击改 1 小时 1 次。
4. 取消打盹及其全部连带表现。
5. 设置页改 4 行（开关 / 成长值 / 好感 / 等级 / 诊断）。
6. v1 存档迁移（留成长值、道具、时间戳；好感 0；三属性丢弃）。

**Non-Goals（明确不做）**

- 不改窗口形态：透明无边框浮层、置顶、拖动、位置持久化、关闭即销毁 —— 全部沿用 v1。
- 不改图集与 `pet.json` 几何契约；不换美术资源。
- 不新增宿主字段类型、不抬 `apiVersion`（避免扩展只能在更新的宿主上装）。
- 不做成长值的分级/解锁/功能（grill Q4=A）、不做道具体系改造（Q1b）、不做多语言文案。

## Decisions

### D-1 状态模型（存档字段与语义）

```text
{
  growth:      number   // 非负整数，只增；+1/小时 +1/每次成功喂食或洗澡；无上限
  favor:       number   // 非负整数，只增；+1/每次成功喂食/洗澡 +1/每次成功点击；无上限
  fish:        number   // 0..20 整数（小鱼干）
  bubble:      number   // 0..20 整数（沐浴泡泡）
  lastInteractAt: number  // 上次成功喂食/洗澡的时间戳（共享冷却基准）
  lastPetAt:   number   // 上次成功点击的时间戳（1 小时冷却基准）
  lastGrowthAt:number   // 上次成长结算的时间戳（每小时 +1 的基准；重开用于补算）
  lastAfkAt:   number   // 上次挂机奖励结算时间戳（1200 秒基准）
  lastTextAt:  number   // 上次定时文本时间戳（300 秒基准，可选：缺失即视为可从现在开始）
  diagnostic:  string   // 既有诊断位（创建失败/存档失败/未知通道等），只读展示
}
```

**选择**：只保留 8 个数值/时间字段，全部整数或时间戳；三属性字段从结构里**物理删除**（不是置 0）。
**理由**：字段越少，迁移与归一越简单；`favor`/`growth` 只增不减 ⇒ 天生不需衰减器。
**被否决的备选**：① 保留 `hunger/clean/mood` 字段但永不使用（迁移歧义、诊断会误导）｜② 用浮点存成长（显示需要取整、比较麻烦）。

### D-2 状态机（状态 / 触发 / 界面表现 / 退出条件）

| 状态 | 进入方式 | 界面表现 | 退出条件 |
| --- | --- | --- | --- |
| `base`（待机/无瞬时） | 无瞬时动作时恒为此态 | 播 `idle` 轨（原速，**不再有 1.5× 慢放**）；面板隐藏 | 任一瞬时动作或拖动开始 |
| `transient.feed` | 喂食成功 | 播 `eating` 轨一轮（约 1.6s）+ 气泡（喂食反馈，4s） | 一轮播完（或页面锁存到期） |
| `transient.bathe` | 洗澡成功 | 播 `waving` 轨一轮（约 1.4s）+ 气泡（洗澡反馈，4s） | 同上 |
| `transient.petted` | 点击（无论冷却与否） | 播 `waving` 轨一轮 + 气泡（成功=摸头反馈 / 冷却=冷却文本，4s） | 同上 |
| `transient.perf` | 每 60 秒随机抽中 | 播该轨一轮（1.4–1.8s），**无气泡** | 一轮播完 |
| `panel`（叠加态） | 指针悬停宠物或面板、且有键盘焦点（`focusOpened`） | 面板出现（两枚图标 + 悬停提示） | 指针离开且无焦点；拖动开始立即关闭 |
| `bubble`（叠加态） | 互动反馈 / 定时文本 | 气泡显示 4s | 4s 到期、或被新的互动反馈替换 |

**瞬时动作的唯一来源标记**（沿用 v1 的 D-1 修复）：入口在写 `transient` 时同时写 `transientSelf: boolean`（自发表演 = `true`，真实互动 = `false`），视图输出 `anim.self`，页面据此决定"播完是否折回待机"。**必须保留**该机制，否则"随机抽到吃饭"与"玩家点喂食"无法区分（v1.0.1 的 D-1 缺陷）。

**被否决的备选**：① 用状态字符串区分来源（v1.0.0 的做法，正是 D-1 缺陷根因）｜② 页面按本地轮长自行折回（`prefers-reduced-motion` 下页面轮长 > 入口时长，会掐掉玩家刚点的动作）。

### D-3 节拍与定时器（全部在入口，`api.timer` 整数秒）

| 定时器 id | 周期 | 职责 | 清理 |
| --- | --- | --- | --- |
| `pet-tick` | 60 秒 | 结算成长（累计满 3600 秒 +1）、结算挂机奖励（满 1200 秒各 +1）、必要时 `rev++` 推送 | 销毁窗体时清（不改数值） |
| `pet-perf` | 60 秒 | 随机抽一条演一轮（7 项，`transientSelf=true`） | 同上 |
| `pet-text` | 300 秒 | 从 1..当前等级的并集里取一条文本（气泡 4 秒） | 同上 |
| `pet-bubble` | 一次性 4000ms | 气泡到期清空 | 清空时先 clear |
| `pet-transient` | 一次性 `ceil(轮长/1000)` 秒 | 瞬时动作到期清 `transient`/`transientSelf` 并 `rev++` 推送（v1 R54） | 同上 |

**两条必须写死的细节（来自 validation 的 S1 与 P2）**：

- **关闭显示期间不计成长**（用户裁定）：销毁浮层窗口时 MUST 把 `lastGrowthAt` 推进到当前时刻；重新打开后从当时重新计时 ⇒ 关三天再开**不会**一次涨 72 点。
- **互动重置挂机计时**：任何成功互动（喂食/洗澡/点击）与拖动结束后 MUST 把 `lastAfkAt` 推到当前时刻，下一次挂机奖励在之后 1200 秒。

**选择**：文本用独立 `pet-text`（300 秒），不与 `pet-perf` 复用；气泡用一次性定时器。
**理由**：三个节拍互相独立、互不取消（spec `pet-favor` 的"与动作节拍互不干扰"scenario）；`api.timer` 只收整数秒，300/60/3600 都合法。
**被否决的备选**：① 一个 60 秒定时器里用计数器派生 300 秒（耦合、测试难）｜② 文本用 `setInterval` 与 perf 同一 id（同 id 会被后者覆盖）。

### D-4 冷却判定（顺序与边界）

判定顺序**固定为：冷却 → 库存 → 结算**（任一不满足整体拒绝，不产生部分副作用）：

```text
喂食/洗澡：now - lastInteractAt >= 600_000 ?
  ├─ 否 ⇒ 拒绝（气泡"再等等"），不消耗、不改值
  └─ 是 ⇒ 对应道具 >= 1 ?
        ├─ 否 ⇒ 拒绝（"没有小鱼干/泡泡"），不消耗、不改值
        └─ 是 ⇒ 道具 -1、growth +1、favor +1、lastInteractAt = now、播动画 + 气泡
点击：now - lastPetAt >= 3_600_000 ?
  ├─ 是 ⇒ favor +1、lastPetAt = now、摸头动画 + 成功气泡
  └─ 否 ⇒ 数值不变，但**仍播摸头动画** + 冷却文本（6 条随机 1 条）
```

**边界**：时间戳缺失/非法（NaN、负数、未来时间）⇒ 一律视为"已到期"（宁可给用户互动，也不要永久卡死）；`now` 回拨（系统改时间）⇒ `now - last < 0` 同样视为已到期。
**被否决的备选**：① 先判库存再判冷却（无道具时会误报"没有小鱼干"，而实际是冷却中，误导）｜② 冷却按 kind 分开（grill Q2 明确共享）。

### D-5 等级映射与文本取样

阈值表（累计好感下界）：`[0,20,50,90,140,200,280,380,500,650]` → 10 个名称（grill D1）。

```text
levelOf(favor) = 满足 thresholds[i] <= favor 的最大 i（i 从 0 计）+1（对外 1..10）
pool(level)    = 文本 L1..L{level} 的并集（第 N 级 = N×12 条）
pick(pool, last) = 均匀随机，且 ≠ last（相邻去重；候选数 ≥12 恒成立）
```

**理由**：均匀随机让"低等级文本在高等级仍会出现"（符合"高等级可显示低等级"），且不需要权重配置。每级 **12 条**（共 120 条）——用户在 validation 环节选择"扩到 12 条"以推迟重复。
**被否决的备选**：① 按等级加权（高等级文本更常出现）——会让"每级 10 条"的低等级文本变得罕见，与用户意图相反｜② 洗牌轮播（每条必出一次）——需要额外持久化轮播游标。

### D-6 气泡优先级与丢弃策略

- 互动反馈（喂食/洗澡/点击成功/点击冷却/无道具/冷却中）**优先级最高**：立即替换当前气泡，并把 `pet-bubble` 重排为 4000ms。
- 定时文本（300 秒）**优先级最低**：若此刻气泡正被占用（互动反馈未过期），**本次直接丢弃**，不排队、不补发（spec `pet-favor` 的"丢弃"scenario）。
- 气泡外观与位置沿用 v1（精灵上方、玻璃底、白字、最大宽度限制）。

**被否决的备选**：① 定时文本排队（会在互动后突然冒出一句陈旧文本）｜② 定时文本强行覆盖互动反馈（会让玩家看不到"没有小鱼干"这类关键反馈）。

### D-7 存档迁移与归一

| 情况 | 处理 |
| --- | --- |
| v1 存档（有 `hunger`/`clean`/`mood`） | 保留 `growth`/`fish`/`bubble`/`lastInteractAt`/`lastPetAt`/`lastSeen`；`favor = 0`；`lastGrowthAt` 缺失 ⇒ = `now`（不补算历史）；删除三属性字段 |
| 字段非数字 / 负数 | 数值字段归 0；道具钳到 `[0,20]`；时间戳视为已到期 |
| 存档整体损坏（JSON 解析失败） | 用初始状态启动 + 诊断位写"存档损坏，已重置"，不阻止启动 |
| 设置键残留 `pet.hunger`/`pet.clean`/`pet.mood` | 迁移时删除这三个键（`api.settings` 无删除方法 ⇒ 置空串/0 并在 manifest 中不再声明，宿主设置页不再渲染未知键） |

### D-8 面板与数值展示（validation 环节修订：面板显示等级名，仍不显示数值）

- **面板 = 两枚图标（喂食/洗澡）+ 一行只读等级名**（如「心有灵犀」），**仍不显示任何数字**（成长值与好感精确值只在设置页）。
- 用户在 validation 环节明确选择"面板显示当前等级名"，因此本决定**部分推翻** v1 的 Q13（"面板不显示属性"）：Q13 的原文针对的是**数值**，本次显示的是**等级名**（一个词），不泄露精确数字。
- 等级名 MUST 随状态推送即时更新（面板开着时升级也会变）。
- **理由**：等级是"看得见的陪伴进度"，一个词对面板的侵入远小于一排数字；也让"挂机一天有没有变化"无需进设置页即可感知。
- **被否决的备选**：① 面板显示 `favor/650`（数字，违 Q13 的原始意图）｜② 面板加进度条（面板高度增加、且与设置页重复）。

### D-9 错误与空态（用户可见中文文案）

| 场景 | 气泡文案（示例，最终以 `notes/texts.md` 的集合为准） | 可否重试 |
| --- | --- | --- |
| 道具不足 | "没有小鱼干了" / "没有沐浴泡泡了" | 等挂机奖励（1200 秒）后可重试 |
| 共享冷却中 | "刚互动过啦，让我歇一会儿～" | 600 秒后自动恢复 |
| 点击冷却中 | 冷却集合 6 条随机一条 | 3600 秒后自动恢复 |
| 浮层创建失败 | 不弹气泡；诊断位写"创建浮层失败"（设置页可见） | 用户重开开关 |
| 存档写入失败 | 诊断位写"存档写入失败" | 下一次结算自动重试 |
| 未知通道/未知互动 | 不弹气泡；诊断位记录（沿用 v1） | — |

**空态**：无存档 = 首次安装（favor 0、growth 0、道具 3/3、等级"初次见面"）；面板在"两枚图标都不可用"时（道具 0 且冷却中）图标保持 `aria-disabled` 样式但仍可 Tab 聚焦并显示提示。

### D-10 取消打盹的连带清理

删除：`sleep` 状态与判定、`SLEEP_AFTER_MS`、`打盹中（Zzz）` 文案、`pet-perf` 的睡眠门控、`idle` 轨 1.5× 慢放、设置页/视图里任何 sleep 字段、测试中的睡眠用例（改写为"长时间无交互仍活跃"的反向断言）。

## UX 与交互流程

**主路径（喂食）**

1. 鼠标移到精灵上 ⇒ 面板淡入（指针在宠物或面板上保持显示）；面板顶部一行只读等级名（如「初次见面」）。
2. 悬停「喂食」图标 ⇒ 图标上方即时出现"喂食"提示（无原生 title）。
3. 点击 ⇒ 入口校验（冷却 → 道具）⇒ 成功：播放吃饭动画一轮、气泡显示喂食反馈 4 秒、`growth+1`、`favor+1`、鱼干 -1。
4. 动画播完回待机；气泡 4 秒后消失；面板在指针离开后立刻关闭。

**失败路径**

- 冷却中：点两枚图标都得到"再等等"类气泡；**不消耗**。
- 无道具：得到"没有小鱼干/泡泡"；**不消耗、不改值**。
- 点击冷却中：摸头动画照播 + 冷却文本（6 条随机）。

**定时路径**：每 60 秒随机演一轮（无气泡）；每 300 秒显示一条等级文本（4 秒）；每 3600 秒成长 +1；每 1200 秒挂机奖励各 +1（均无可见提示，避免打扰）。

**键盘可达性**：Tab 顺序 = 精灵 → 喂食 → 洗澡（面板打开时）；Enter/Space 触发；焦点环白色 2px（沿用 R53 基线）；`aria-label` 逐字「喂食」「洗澡」；`aria-disabled` 用于不可用态（不设原生 `disabled`，保证仍可聚焦与读屏）。

**拖动与键盘**：拖动仅鼠标；拖动中面板立即关闭且不重开（沿用 v1 的 `panelShouldOpen`）。

## UI 视觉规范

**风格**：沿用现有扩展风格（`extensions/rdp` / `extensions/webapp` 的基线 + 本扩展 v1 面板），玻璃底面板、小间距、白色描边图标、白色焦点环。

**只用宿主 token**（清单见 `docs/extension-api/themes-settings.md` §「Token 全量参考」，25 个）：

| 用途 | 取值 |
| --- | --- |
| 面板背景 | `var(--bg-panel)` + 半透明叠层（`color-mix` 或既有 `--hover-bg`，不新造色值） |
| 主文字 / 次要文字 | `var(--fg)` / `var(--fg-dim)` |
| 高亮/标题 | `var(--fg-bright)` |
| 边框与分隔 | `var(--border)` |
| 悬停背景 | `var(--hover-bg)` |
| 焦点环 | 白色 2px（**沿用 v1 的 Q17/R53 用户明确要求**，属"白色线条"这条视觉裁定的延续，不是新造 token） |
| 图标描边 | 白色（同上，Q17 的"透明底 + 白色线条"） |
| 字号 | `var(--font-size)`（13px）/ `var(--font-size-sm)`（12px，用于悬停提示与气泡） |
| 图标尺寸 | 22px（沿用 v1 的 `.act` 尺寸，不消费 `--icon-size`，因宿主只声明未使用） |
| 圆角 / 间距 | `--radius-lg` 10px（面板）、8px（图标按钮）——按 rdp 的既有布局变量档位 |

**七条硬约束逐条落实**

1. **零自造色值**：CSS 里只有 `var(--…)`；白色仅出现在"图标描边/焦点环"这两处**用户明确要求**的位置（v1 已如此，且有测试钉着 `stroke:#fff`）。
2. **只用宿主 token**：本设计不需要新 token；`--radius`/`--radius-lg` 属扩展自有布局变量（rdp 先例）。
3. **标签列固定宽、左对齐**：设置页由宿主渲染（`progress`/`status` 行自带对齐），扩展不自定义。
4. **窄窗口堆叠**：浮层窗 220×460，面板两枚图标一行（22px×2 + 间距 8px = 52px）+ 上方一行等级名（`var(--font-size-sm)`、单行省略），远小于面板宽度；气泡 `max-width: 200px` 自动换行。
5. **下拉说明写在选项内**：本轮无下拉字段。
6. **模态框只能按钮关闭**：本轮无模态框。
7. **中文文案**：全部界面文案中文；错误文案可执行（"没有小鱼干了"、"刚互动过啦"）。
