## ADDED Requirements

### Requirement: 成长值 SHALL 只增不减，来源为「每次成功喂食或洗澡 +1」与「每连续运行满 1 小时 +1」

成长值 MUST 是**非负整数**，MUST NOT 有任何衰减或清零逻辑；MUST NOT 参与等级判定、MUST NOT 解锁任何动作或文案（用户裁定：纯累计数字）。每次成功喂食或洗澡 MUST 使成长值 +1；连续运行每满 3600 秒 MUST 使成长值 +1（进程内按累计时长发放，重开时按存档里的上次结算时间补算，单次补算上限 24 小时，防止改系统时钟刷值）。**关闭「显示宠物」期间 MUST NOT 计入成长**：销毁浮层窗口时 MUST 把"上次结算时间"推进到当前时刻，重新打开后从那一刻重新计时。

#### Scenario: 互动使成长值 +1

- **WHEN** 玩家点击「喂食」（或「洗澡」）且本次互动成功（有道具、不在冷却期内）
- **THEN** 成长值恰好 +1（其余数值不因此变动）

#### Scenario: 连续运行满一小时使成长值 +1

- **WHEN** 宠物连续运行满 3600 秒（期间无论是否互动）
- **THEN** 成长值恰好 +1；每次结算后计时重新开始

#### Scenario: 重开时按离线时长补算

- **WHEN** 扩展重新启动，且距存档里的上次结算时间已过 N 个整小时
- **THEN** 成长值一次性 +N（N 以 24 为上限），本次启动后的计时从当前时刻重新开始

#### Scenario: 成长值不驱动任何功能

- **WHEN** 成长值为任意数值（0、1、100、10000）
- **THEN** 等级、可见文案集合、随机动作集合、面板图标集合完全相同（成长值只用于展示）

#### Scenario: 关闭显示期间不涨

- **WHEN** 玩家关掉「显示宠物」持续 3 小时后重新打开
- **THEN** 成长值 MUST NOT 因这 3 小时增加（销毁窗口时已把上次结算时间推到当时），重新打开后从 0 开始计时

### Requirement: 好感值 SHALL 只增不减且无上限，来源为「每次成功喂食或洗澡 +1」与「每次成功点击宠物 +1」

好感值 MUST 是**非负整数**且 MUST NOT 设上限（用户裁定：满级后继续累加）；MUST NOT 因任何原因减少或清零。每次成功喂食或洗澡 MUST 使好感值 +1；每次**冷却已过**的点击 MUST 使好感值 +1；处于点击冷却期内的点击 MUST NOT 改变好感值。

#### Scenario: 喂食/洗澡增加好感

- **WHEN** 喂食或洗澡成功
- **THEN** 好感值恰好 +1

#### Scenario: 点击增加好感（冷却已过时）

- **WHEN** 距上次成功点击已超过 3600 秒，玩家点击宠物
- **THEN** 好感值恰好 +1

#### Scenario: 点击冷却期内点击

- **WHEN** 距上次成功点击未超过 3600 秒，玩家点击宠物
- **THEN** 好感值**保持不变**（但动画与冷却文本按 `pet-interaction` 的规定表现）

#### Scenario: 满级后继续累加

- **WHEN** 好感值已经达到最高级阈值（650）后再次成功互动
- **THEN** 好感值继续 +1，等级保持最高级（不回落、不封顶）

### Requirement: 好感值 MUST 按固定阈值映射到 10 个等级，且等级 MUST 单调不减

阈值（累计好感值，闭区间下界）：`0` 初次见面 / `20` 点头之交 / `50` 渐渐熟悉 / `90` 开始依赖 / `140` 相互惦记 / `200` 心有灵犀 / `280` 形影不离 / `380` 无话不谈 / `500` 彼此唯一 / `650` 命定相伴。等级 MUST 取"满足阈值的最大级"；MUST NOT 出现等级下降；初始好感 0 MUST 为第 1 级。

#### Scenario: 初始等级

- **WHEN** 首次安装（无存档）或迁移后好感为 0
- **THEN** 等级为第 1 级「初次见面」

#### Scenario: 跨越阈值升级

- **WHEN** 好感值由 19 增加到 20
- **THEN** 等级由「初次见面」变为「点头之交」

#### Scenario: 不降级

- **WHEN** 任何操作之后
- **THEN** 等级不低于此前的等级（好感值只增不减，故等级不可能下降）

### Requirement: 载入 v1 存档时 MUST 保留成长值、道具数量与时间戳，把好感值初始化为 0，并丢弃三属性字段

迁移 MUST 保留 `growth`、`fish`、`bubble`、`lastInteractAt`、`lastPetAt`、`lastSettledAt`（v1 的实际字段名；本文档早前误写为 `lastSeen`，已更正）的既有值；MUST 把 `favor` 初始化为 0；MUST 忽略并不再写回 `hunger`/`clean`/`mood`/`growthRate` 等 v1 字段。任何字段缺失或非法 MUST 按各字段既有的 `sanitize*` 规则归一（非数字 ⇒ 0；道具越界 ⇒ 钳到 [0,20]；时间戳非法 ⇒ 视为已到期），MUST NOT 因存档损坏而阻止启动。

#### Scenario: 从 v1 存档升级

- **WHEN** 存档里存在 `growth: 120`、`fish: 7`、`bubble: 5` 与 `hunger: 40`、`clean: 20`、`mood: 70`
- **THEN** 载入后 `growth = 120`、`fish = 7`、`bubble = 5`、`favor = 0`，三属性字段不再存在

#### Scenario: 损坏字段不阻止启动

- **WHEN** 存档里 `favor` 为 `"abc"`、`fish` 为 `-3`
- **THEN** 宠物正常启动，`favor` 归一为 0、`fish` 归一为 0，并记录一条诊断
